## Context and Orientation

This repository is `DallasCrilleyMarTech/genie-cli`. The product lives in the `genie/` subdirectory as a TypeScript CLI package with Bun/Node tooling. The package manifest is `genie/package.json`; it defines `build` as `tsc -p tsconfig.json`, `test` as `vitest run`, `typecheck` as `tsc -p tsconfig.json --noEmit`, and `doctor:flake` as `bun run scripts/quantify-doctor-flake.ts`. The executable entry point is `genie/src/bin/genie.ts`, which calls `cli(process.argv.slice(2))` from `genie/src/cli.ts`.

The main architectural pressure point is `genie/src/cli.ts` at roughly 1,113 lines and `genie/src/cli/parse.ts` at roughly 987 lines. `genie/src/cli.ts` currently mixes command usage text, command dispatch, JSON/plain output handling, mutation safety prompts, config/preset command orchestration, and direct command execution for `run`, `design`, `debug`, `commit`, `review`, `update`, and provider/config/preset/completion flows. `genie/src/cli/parse.ts` currently owns root command detection plus detailed token parsing for review, update, completion, run/design, debug, commit, config, and presets. `genie/src/cli/types.ts` defines the shared `ParsedCommand` union that the parser and dispatcher both use.

Existing feature-specific code already follows a more modular pattern. `genie/src/design/command.ts`, `genie/src/debug/command.ts`, `genie/src/commit/command.ts`, `genie/src/review/command.ts`, `genie/src/update/command.ts`, and the files under `genie/src/config/`, `genie/src/presets/`, `genie/src/providers/`, and `genie/src/execution/` encapsulate command-specific logic. The refactor should lean into this existing pattern by moving more CLI shell logic into `genie/src/cli/` helpers rather than creating a second orchestration style.

Tests are already broad and are the main safety net. Key suites include `genie/test/cli.parser.test.ts` for parse stability, `genie/test/cli.help.integration.test.ts` for usage/help output, `genie/test/cli.design.integration.test.ts` for the new design command, `genie/test/cli.review-json.integration.test.ts` and `genie/test/review.command.test.ts` for review behavior, `genie/test/cli.exit-codes.integration.test.ts` for exit-code mapping, `genie/test/cli.machine-json.integration.test.ts` and `genie/test/output.contract.test.ts` for JSON envelopes, and `genie/test/cli.completion.integration.test.ts` for shell completions. The current local verification baseline is green: `npm test` passed with `34` test files and `146` tests, and `npm run typecheck` plus `npm run build` both succeeded.

Continuous integration is defined in `.github/workflows/ci.yml`. It already installs dependencies with `bun install --frozen-lockfile`, runs typecheck/test/build, links the installed binary with `bun link`, verifies `genie --help`, verifies `genie providers list --json`, runs a mocked-provider plain execution smoke test, and validates installed-binary exit code behavior for usage (`2`), auth (`3`), and timeout (`124`). Recent GitHub Actions runs for `main` and the release sign-off PR were successful. This means the next sprint should not prioritize more generic CI expansion unless new gaps appear during refactoring.

Release state matters here. `docs/plans/2026-03-06-release-readiness-sweep.md` records `v0.1.0` as released and calls out the remaining follow-up items: close or re-scope the release-readiness TD item, split `genie/src/cli.ts` and `genie/src/cli/parse.ts`, reduce the `cursor-agent` workspace-trust waiver, and decide safe post-release hygiene around tooling artifacts. The README in `README.md` now documents `genie design`, the expanded command surface, and the provider prerequisites, including the fact that `cursor-agent` may still require authentication and trusted workspace approval in the current directory.

The provider subsystem is intentionally simple. `genie/src/providers/registry.ts` exports the provider adapter list in stable order. `genie/src/providers/cursor-agent.ts` shells out to the `cursor-agent` binary with mapped arguments and returns extracted response text. `genie/src/providers/doctor.ts` asks each adapter whether it is available and authenticated, then returns a status envelope with optional hints. At present there is no provider-specific remediation for workspace trust failures; either the adapter or the doctor layer will need to grow clearer hints, or release policy must be changed explicitly and documented.

Repo hygiene is the last active paper cut. The root `.gitignore` does not currently ignore `.omc/`, `.omcodex/`, or `error.log`, and `git status --short --branch` in the root shows those files as untracked. Earlier release work had to relocate similar artifacts manually to achieve a clean worktree. The goal is not to hide important project files; it is to make local session/runtime artifacts live outside the release surface or be explicitly ignored if they are always disposable.

## Plan of Work

Begin by clearing the stale review queue so the repository state matches reality. Run `td approve td-682e24` after confirming that the release readiness sweep really is complete and that its remaining items are captured elsewhere. Then skim the shipped `design` command surfaces in `README.md`, `genie/src/design/command.ts`, and `genie/test/cli.design.integration.test.ts`, and if there is no mismatch, approve `td-32ae0d`. If approval reveals follow-up work, create or update TD items immediately so no knowledge remains only in this plan.

The first substantive code change is the CLI modularization. Split `genie/src/cli.ts` by responsibility, not arbitrarily by line count. The command usage/help text should move into a dedicated helper such as `genie/src/cli/help.ts` exporting functions like `usage(topic?: HelpTopic): string`. JSON/plain output writers and error/render helpers should move into a file such as `genie/src/cli/output.ts` so the root `cli()` function becomes orchestration instead of a monolith. If the current `cli()` function interleaves command parsing and command execution, introduce a thin dispatcher helper such as `runParsedCommand(parsed: ParsedCommand, runtime: CliRuntime): Promise<number>` in a file like `genie/src/cli/dispatch.ts`. The stable interface requirement is that `genie/src/bin/genie.ts` continues importing `cli` from `genie/src/cli.ts`, and downstream behavior remains unchanged.

Refactor `genie/src/cli/parse.ts` next. The main target is to stop one file from owning every subcommand's token parsing logic. Create focused parser helpers under `genie/src/cli/parse/` or equivalently named files, for example `review.ts`, `prompt-command.ts`, `config.ts`, `presets.ts`, and `shared.ts`. Keep `genie/src/cli/parse.ts` as the public entry point that handles root command dispatch and strict-command fallback decisions, but move subcommand token walking into these helpers. The parser should continue returning the same `ParsedCommand` union from `genie/src/cli/types.ts`; do not introduce incompatible parse result types.

While refactoring, expand tests only where the new boundaries need protection. If extracting help text changes the shape of string assembly, keep `genie/test/cli.help.integration.test.ts` green and add unit-level assertions only for newly created pure helpers. If parsing is split into subfiles, preserve `genie/test/cli.parser.test.ts` as the source of truth for public behavior. Avoid rewriting passing integration tests just to match internal structure.

Once the structural refactor is green, address `cursor-agent`. Start by reproducing the current doctor output in a clean or simulated workspace and inspecting whether the failure mode is “binary missing,” “auth missing,” or “workspace trust required.” Then choose one of two implementations and record the choice in the Decision Log: either enhance `genie/src/providers/cursor-agent.ts` / `genie/src/providers/doctor.ts` with provider-specific trust hints and possibly a preflight check for trusted workspace state, or document an explicit bootstrap recipe in `README.md` and `docs/release-checklist.md` if no reliable machine check exists. The minimum acceptable outcome is that a novice can distinguish an install problem from a trust problem without guesswork.

Finish by resolving repo hygiene. Determine whether `.omc/`, `.omcodex/`, and `error.log` are always ephemeral local artifacts. If they are, update the appropriate ignore file at the repository root so they no longer appear in `git status`. If any of them can contain intentionally shared project state, move the generators or workflows to emit them outside the repository instead. After the change, re-run `git status --short --branch` to confirm the working tree stays clean under normal usage.

## Idempotence and Recovery

The validation commands are safe to run repeatedly. TD approvals are not reversible in the same way as code edits, so inspect `td context` first and create follow-up tasks rather than delaying approval indefinitely. The refactor should be performed in small, reviewable commits or patches so that individual extraction steps can be reverted with normal git history if a regression appears. Avoid deleting existing tests; if a test fails during extraction, either fix the code to preserve behavior or explicitly record the contract change and update docs.

Ignore-rule changes must be treated carefully. Only ignore `.omc/`, `.omcodex/`, or `error.log` if they are confirmed to be disposable local artifacts. If there is uncertainty, prefer relocating artifact generation outside the repository over adding a broad ignore. After each hygiene change, use `git status` to verify the outcome rather than assuming it worked.

## Interfaces and Dependencies

The CLI entry point must remain:

    In `genie/src/bin/genie.ts`:

        import { cli } from '../cli.js'
        await cli(process.argv.slice(2))

The parser public interface must remain:

    In `genie/src/cli.ts`:

        export { parseArgv } from './cli/parse.js'

and in `genie/src/cli/parse.ts`:

        export function parseArgv(argv: string[]): ParsedCommand

`ParsedCommand`, `GlobalOptions`, `RunOptions`, `ReviewOptions`, `MutationSafetyOptions`, and `HelpTopic` should continue living in `genie/src/cli/types.ts` unless there is a compelling reason to split types further. If new helper files are introduced, they should consume and return these existing types rather than inventing parallel type systems.

Provider doctor output must continue to use the `ProviderDoctorStatus` shape in `genie/src/providers/doctor.ts`:

    export type ProviderDoctorStatus = {
      provider: ProviderId
      available: boolean
      authenticated: boolean
      availabilityDetails?: string
      authDetails?: string
      hint?: string
      latencyMs: number
    }

If `cursor-agent` gains better diagnostics, prefer enhancing the `availabilityDetails`, `authDetails`, or `hint` fields over changing the public JSON envelope shape.

Dependencies are intentionally light. Runtime code depends on `zod` and internal helpers only. Tooling depends on `typescript`, `vitest`, Bun, Node, and GitHub Actions with `oven-sh/setup-bun@v2`. Keep new dependencies out of scope unless a clear tooling gap makes them necessary.
